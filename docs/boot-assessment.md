# 开屏评估：用户 Amadeus「红莉栖 CG 底图 + 世界线」方案能否移植进宣传页

> 结论先说：**建议移植，而且应该移植。** 5195 的开屏在“氛围 / 叙事 / 层次”上明显强于我们现在“纯黑星图 + 世界线 + 乱码按钮”的版本；它与我们的橙色辉光管数字、IBM 乱码按钮、世界线光点本来就是同一套语言（我们的数字阶段早就是照它做的），缺的只是底图。推荐方案：**保留我们现有的“数字变动 → 世界线汇聚 → 进入按钮 → 点击进入”流程与代码，只把开屏底图换成红莉栖 CG（+ 暗角/扫描线/黑边/HUD），并把汇聚点下移到按钮处、让世界线避开脸部。** 已做出可预览的原型：`?boot=amadeus`（默认开屏不变）。

## 3. 站在视觉设计师角度的评估
**好在哪里**
1. **叙事钩子强**：开屏就是“红莉栖从镜头里盯着你”——对《命运石之门》观众是一眼可认的“监控 / 观测”意象（CAM 04 HUD + 扫描线），一下就交代“观测者—世界线”的主题。我们现在的纯黑星图很安静，但**没有主体**，观众第一眼没有可看的东西。
2. **层次与节奏**：数字阶段 CG 在后面暗暗透出（人脸轮廓若隐若现），数字锁定后 CG“亮起来”，这个“压暗→提亮”本身就是一次情绪释放；我们的版本是“黑→黑上出线”，释放点弱。
3. **色彩统一**：CG 的青绿色实验室 + 红棕发 + 橙色辉光管，正好是我们章节底图（青灰/暖黄）和橙色数字的同色系；纯黑底反而与后面的彩色章节底图“断层”，用 CG 开屏后，开屏→首屏的过渡更连贯（深青绿暗场 → 实验室场景）。
4. **信息密度合适**：只有数字、一条线、一句台词、一个 HUD 角标、一个 logo，克制；画面主体是 CG，不挤。

**不足 / 风险**
1. **画面主体与世界线的争抢**：CG 中间是脸，我们现在“左上往下汇聚到屏中偏下”的 6 条线会穿过下巴/领口；5195 的做法是线只走底部三分之一。需要让线避开脸（见方案）。
2. **版权/来源**：该图是用户项目里的 `ready-cg-owner-r3.png`，来源应为官方 CG（含真由理、Daru 等角色），我无法从文件本身确认出处与授权，宣传页里按“官方素材，仅供课堂展示”处理（与我们已有的微波炉/章节底图同口径），ASSETS 需登记；若老师要求“原创/授权清晰”，这是已有素材里风险最高的一张，因为是**满屏、第一眼**。
3. **与首屏红莉栖 E-mote 的重复**：开屏 CG 是红莉栖近景，进入后首屏又是红莉栖 E-mote 立绘。5195 自己的流程也是这样（CG → Daily 白大褂），而且是**有意的叙事**（“她注意到你了→走到房间里”）。风险在于连续两次“同一个人”会稍显重复——缓解办法：进入转场时 CG 先淡出到暗、再显出首屏；转场里不要让两个红莉栖同时清晰出现；本页首屏的红莉栖是常服 E-mote，与白大褂 Daily 不同，反而有“换装”的新鲜感。可接受。
4. **放大模糊**：见上，1672 宽；在 1920×1080 内无感，2560+ 要靠扫描线/颗粒/暗角遮掩，可加 1–2px 的 `image-rendering` 之外的处理（轻微锐化版本在构建时生成）。
5. **加载与体积**：2.1MB PNG 不能直接用；转 WebP 后约 140KB（原型已做，q86 看不出损失）；开屏要在模型加载的同时预载，CG 加载失败时回退到现在的纯黑底（`bgfield`），不会卡死。
6. **与我们已定的需求冲突点**：第六轮要求“去掉 logo”“世界线从左上流出、向下向右汇聚”。5195 有 logo（左上）与底部横向世界线。**需要用户确认**：开屏是否仍不放 logo（建议不放，避免与首屏左上 logo 重复；用 HUD 角标代替）。

## 4. 与我们现有元素是否协调
| 元素 | 判断 |
|---|---|
| 橙色辉光管数字 | 已是同一套（5195 的数字就是我们的参照），叠在 CG 上与 5195 几乎一致，**协调**（见 `compare-2-digits.jpg`） |
| IBM 乱码进入按钮 | 协调；叠在 CG 的白衬衫/领口上需要更强的局部暗垫（5195 的做法是底部渐变暗），原型已加；乱码代码行叠在衣服纹理上会糊，建议 CG 模式下去掉第 3 行代码/降低透明度 |
| 星图式世界线（6 条，发光节点） | **风格协调**（橙/杏色细线 + 白色光点），但在 CG 上线更容易“花”：节点光斑落在人物面部/头发上很抢眼 → 需要避让（见方案） |
| 指针（齿轮） | 协调，无冲突 |
| 底部进度条 | 进入后才出现，无冲突；CG 暖青绿与进度条的星图线颜色一致 |
| 开屏黑背景 + 代码列 + 星图网格（`bgfield.js`） | 被 CG 取代；可只保留“极淡代码列”在 CG 之上，也可完全不用。建议**不保留**，避免“CG + 网格 + 代码列 + 世界线 + HUD”叠得太满 |

## 5. 明确建议与移植方案
**建议：采用。** 具体：

直接沿用（已在原型里验证）
- 流程不变：数字变动（含 1.048596 落定）→ CG 提亮 → 世界线汇聚 → 进入按钮出现（乱码）→ 悬停解码 → 点击/Enter 进入；模型加载约束不变（按钮加载态/不可点/失败降级可进）。
- CG 作为底图：`inset:4.5% 0` 的上下黑边画幅 + 暗角 + 扫描线（已有 `.bt-vhs`）+ 底部渐变暗垫；数字阶段 CG 以 0.5 透明度、亮度 .55 垫在后面，进入 `flow` 阶段提到 0.86 亮度。
- 右上 `CAM 04 FUTURE GADGET LAB / 日期 / 实时时钟` 的 HUD（原型已做，纯文本，代码自写）。

需要适配（建议下一步做，我还没做，等你拍板）
1. **世界线路径避开脸**：CG 里脸占中间 30–65% 宽、10–70% 高。改法一：汇聚点设在按钮处（屏幕 70% 高处，已设 py=0.7），6 条线改成**从左缘与底缘进入**、沿画面左下的沙发/茶几区域和底部三分之一汇聚（不穿过脸）；改法二（更接近 5195）：线沿底部三分之一整体从左向右、起伏、汇入按钮。两者都符合“从左往右”的原始要求；“左上角起点”的要求需要你确认是否放宽。
2. 节点光斑在 CG 模式下半径 ×0.7、数量 ×0.7，线整体透明度 ×0.8，避免与人物细节争抢。
3. CG 模式下进入按钮后方加 5195 式的底部渐变暗垫（已加），并把按钮底下两行代码降到 .2 透明度或去掉。
4. 进入转场：CG 先 0.4s 变暗 + 轻模糊再淡出（与 5195 一致），首屏 E-mote 红莉栖随后出现，避免“两个红莉栖同时清晰”。
5. 资源：构建时由 `1672×941` 原图生成 WebP（≤200KB）+ 可选 2560 宽的轻锐化版；开屏预载；加载失败回退现在的纯黑背景；`prefers-reduced-motion` 时直接静态 CG。
6. 登记 `ASSETS.md`（官方素材，仅供课堂展示）与页面版权说明。
7. e2e：保持现有开屏断言（按钮加载态/不可点/点击进入），新增“CG 模式下底图 WebP 已加载、加载失败回退”两条。
