# 宣传页卡顿排查与优化

日期：2026-10-11（Asia/Shanghai）。项目：`amadeus-resonance-promo-site`。沿用已接手的 Grok 第九轮与 Codex 补修，不涉及正式 Amadeus/VN 工程。

## 确认的问题及处理

| 问题 | 证据 | 处理 |
|---|---|---|
| 人物入场被重播 | `stagefx.js` 同时用 `onfinish` 和超时进入下一段。基线一次正常换页记录到 3 次 Web Animations 启动：退出一次、入场两次 | 入场只能执行一次，正常完成即清理兜底计时器；8 种动效分别验证，快速切换仍由最后一次接管 |
| 屏幕外 SVG 持续触发布局 | Chrome trace 的 `LayoutInvalidationTracking` 指向第四章的 `g.r-spin`；SDK 读取人物位置时触发它留下的布局工作 | 按章节可见性暂停圆环、辉光编号、Logo 齿轮和道具装饰；隐藏的换线覆盖层停止动画 |
| 滚动时全页样式计算与读写交错 | `--bgp` 原先写在 `html`，随后逐章读取位置；8 个全屏底图长期要求独立合成层 | 只更新当前背景；缓存章节几何，尺寸/字体/文案改变时刷新；淡出结束后释放旧背景的合成提示 |
| 大面积模糊与长页面滤镜 | 推近/远景动效给人物及光环所在的大图层逐帧加模糊；世界线色散作用于八章组成的整个 `main` | 推近/远景保留缩放与透明度，去掉整层模糊；色散只作用于视口内的章节 |
| 模型载入打断数字演出 | 两套 PSB 约 205MB / 212MB，官方 `loadData()` 在主线程同步执行，基线换装有约半秒长任务 | 数字阶段并行下载；黑场完全覆盖后释放旧模型、解析新模型并完成首帧预热；撕裂快照覆盖人物时暂停人物与光环 |
| 换线结束时人物又闪一次 | 正常 reveal 和 `finally` 都调用 `reappear()` | 正常路径只入场一次，异常路径保留恢复兜底 |
| 开屏隐藏层持续绘制 | CG 已遮住备用星图，但其 Canvas 循环仍在运行；开屏完全透明后世界线还多运行约一秒 | CG 成功即暂停备用星图，CG 失败恢复；淡出完成即终止开屏绘制 |
| 乱码动画反复重算导航 | 字体/内容尺寸变化触发 ResizeObserver，可能频繁重建底部节点 | 换线期间合并更新，文字还原后统一计算导航；文本更新按读取/写入分批执行 |

## 测量方法

- 本机 Chrome 154、ANGLE Metal / Apple M1，真实 E-mote SDK 与 PSB，串行运行浏览器。
- 对照场景：开屏进入、首屏静止 2.5 秒、依次点击七个章节、世界线换装。
- 1440×900 / DPR 1；另测 1920×1080 / DPR 2。模型分辨率沿用原设置。
- `scripts/profile-performance.mjs` 记录 rAF 间隔、超过 50ms 的间隔、Long Tasks、Chrome Layout/RecalcStyle/TaskDuration，以及人物 Web Animations 启动次数。
- `scripts/verify-performance.mjs` 独立检查入场重启、连续换页最终位置、离场暂停、黑场载入和下载失败恢复。
- rAF 是主线程调度间隔，不等于录屏中每帧最终呈现耗时。结果受缓存、随机表情、后台负载影响；没有将单次采样当成所有设备稳定 60fps 的保证。
- 优化前源码副本：`.tmp/performance-before-2026-10-11/`。本轮源文件差异与哈希：`output/playwright/performance/source-changes.patch`、`source-hashes.json`。

## 前后采样结果

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 首屏静止 2.5 秒，布局计算次数（1440 / DPR 1） | 152 | 0 |
| 七次换页，样式计算耗时合计（1440 / DPR 1） | 1182ms | 361ms |
| 七次换页，超过 50ms 的 rAF 间隔（1440 / DPR 1） | 4 / 877 | 1 / 903 |
| 七次换页，超过 50ms 的 rAF 间隔（1920 / DPR 2） | 31 / 584 | 3 / 856 |
| 世界线换装，主线程 TaskDuration 合计（1440 / DPR 1） | 6.39s | 3.26s |
| 世界线换装，最长 rAF 间隔（含黑场） | 567ms | 417ms |

七次换页的采样时段：1440 场景前后分别约 15.4 / 15.5 秒；1920 场景约 17.6 / 17.0 秒。分母是该时段实际记录的 rAF 间隔数。以上保留偶发长帧，未挑选零卡顿片段。

本次最终采样的换装同步解析约 404ms；采样确认解析时 `.sh-black` 透明度为 1、覆盖整个视口且处于 `swap` 阶段。另一次独立回归测得约 234ms，同样发生在完整黑场内。不同运行的耗时会波动。

组件分测（1920 / DPR 2，首屏静止）中，模型一次绘制平均约 3.56ms、光环约 0.17ms；因此没有为这轮优化降低人物分辨率。该数据只描述此场景，不能推广为所有表情/转场的固定成本。

原始记录：`output/playwright/performance/{before,after-final,before-retina,after-retina}/report.json`。初次诊断、中间修改版本也保留在同目录的 `after-first`、`after-retina-first`、`after`，不要混用为最终数据。`before/idle-trace.json` 保存屏幕外圆环触发布局的 Chrome 追踪；`retina-components.json` 保存组件分测。

## 边界

官方 SDK 和 PSB 原件未改。同步解析仍会阻塞主线程；现在将它放在已覆盖画面的黑场里，不能把这项开销宣称为消除。首次开屏的模型载入仍有同步解析开销。

没有同时常驻两套播放器或长期缓存两套 PSB 字节。下载下一套时会短暂持有字节缓冲；挂载仍遵循先释放旧模型、再载入新模型。下载失败时保留当前世界线与人物，页面可继续操作。

八种入场方式、世界线撕裂、数字跳变、A/B 文案、换装和表情交互保留。推近/远景的大范围动态模糊与标题字距动画已移除，替换为原有的缩放、位移与透明度演出；这是本轮有意的视觉取舍。

后续若还要消除 SDK 的同步解析长任务，需要另行评估 Worker/OffscreenCanvas 适配或模型资产瘦身；本轮没有改写官方 SDK，也没有用静态图片替代真实模型。

八种人物动效逐个检查只有一次入场，快速连续切换保持最后目标；真实模型解析的黑场覆盖、失败保留旧世界线、人物离场与返回均有直接断言。布局尺寸为 1920×1080、1440×900、1280×720、1024×768、2560×1440、3440×1440、800×1200、390×844。

最后检查还修正了后台缩放时误清除模型 active 意图的问题，并用真实前后台标签页验证。Playwright 默认焦点模拟会把页面强制保持 visible；首次探测结果保存在 `visibility/focus-emulation-diagnostic.json`，它不能作为后台暂停证据。最终使用隔离 Chrome 与 `noDefaults` 连接，确认 `document.hidden=true`、帧数停止、回到前台自动继续。前后性能采样均在前台进行，该最后修正不改变采样路径；最终构建后的定向返回检查为 4 项通过。

实际查看了优化前/后 B 世界线、本轮定向换装截图和最终前台恢复截图。当前生产预览为 `http://localhost:5287`，需要刷新载入新构建。验证通过不代表所有设备、所有后台负载下均无长帧。
